## P0 · 环境锁定与真人基线（2 天）

### 任务

- [ ] 锁定 FG 版本（建议 2024.1）、机型、机场、scenery tile、气象条件，全部写入 `launcher.sh`
- [ ] 搭建最小 addon 骨架（`addon-metadata.xml` + `addon-main.nas`），确认 `main()` 被正确调用
- [ ] 打通三个接口：telnet(5401) / httpd(5400) / generic protocol(30Hz UDP)
- [ ] 编写遥测采集器原型（Python，收 UDP，落盘 CSV）
- [ ] **用 stock AP 把每个场景各跑 20 次，统计接地指标分布**

### 产出

- `launcher.sh`、`env.lock`（版本与哈希清单）
- 遥测采集器原型
- `baseline.csv`（真人/AP 基线数据）

### 关键决策点

用 `baseline.csv` 反推阈值：

- flag1 的合格线定在 **stock AP 最好成绩之外**（让开 AP 能过但拿不满）
- 场景参数用 `userid` 做 seed 随机化（风向、强度、切变位置），逼选手写鲁棒控制器而非过拟合

### 风险

| 风险 | 缓解 |
|---|---|
| 不同机器帧率差异导致进近表现不可比 | 锁定渲染设置，或直接用固定步长（`/sim/time/speed-up` 归 1 且禁止改动） |
| AP 行为随 FG 版本变化 | 基线数据必须在锁定版本上重采 |

## P1 · 连飞平台 + 判决服务器（4 天）

### 任务

- [ ] 部署私有 fgms（docker 镜像 `flightgear/fgms:0.13.4`），关闭 `relay` / `tracked` / `is_hub`
- [ ] **抓包实测确认**：客户端多开 `--multiplay=out` 是否真的能镜像流量（wiki 与社区反馈冲突）
- [ ] 编写 MP 包解析器：32 字节头（Magic `FGFS` / Version / MsgId=7 / MsgLen / Range / ReplyPort / Callsign）+ XDR 第一部分（ECEF 位置、角轴姿态、速度、角速度）
- [ ] 实现权威时间戳 + 位置差分地速
- [ ] 实现轨迹连续性检查（防瞬移）
- [ ] 实现心跳验签接口（连续 / 无跳号 / 无重复）
- [ ] 实现 challenge 注入（先只做环境类：改风向 / 能见度，判定响应时延与幅度）
- [ ] 实现 flag 下发：`flagN = HMAC(K_server, userid ‖ checkpoint)`

### 产出

- `fgserver/`（判决服务，建议 Python + `construct` 库解二进制）
- `protocol/mp_parser.py`
- 判决规则配置 `rules.yaml`

### 关键决策点

- **所有流量必须强制经过我方服务器**，客户端不留镜像可选项
- 服务端自算地速，客户端上报仅作交叉验证

### 风险

| 风险 | 缓解 |
|---|---|
| MP 基础包可能不含 `vcas` | 动手前抓包确认；用地速差分兜底 |
| XDR / 角轴姿态解码写错导致姿态判据失真 | 先用单机双实例互发做单元测试 |
| 服务器带宽（10Hz × N 人） | 招新赛规模无需担忧；预留横向扩展 |

### 任务

- [ ] flag1：ILS 进近判定逻辑（航向道/下滑道偏离、接地品质、弹跳检测）

- [ ] 场景参数 `userid` 随机化

### 产出

- `ctf-addon/`（Nasal 场景与规则）
- `checker/flag1.py`、`checker/flag2.py`

### 关键决策点

- **允许内置 AP**（已确认，不设飞行手感门槛）

### 风险

| 风险 | 缓解 |

## P3 · 反作弊（7 天）· 关键路径

### 任务分解

| 子项 | 内容 | 估时 |
|---|---|---|
| 框架 | 独立 native 进程（Linux ELF 优先，Windows 可选）、与 launcher 耦合、session ticket | 1 天 |
| L0 | 启动参数白名单、`--fdm` 类型校验、无 `--load-tape` | 0.5 天 |
| L1 | 机型 / scenery 数据目录哈希 | 0.5 天 |
| L2 | 属性树写入审计（telnet / generic / httpd 三个入口都要覆盖） | 1 天 |
| L4 | fgfs `.text` CRC 自检、`/proc/self/maps` 注入扫描 | 1 天 |
| L5 | 自哈希、`PTRACE_TRACEME`、`TracerPid`、RDTSC 时差、断点扫描 | 1.5 天 |
| anti-VM | CPUID / DMI / MAC OUI / 驱动 / 进程 / 时序 | 1 天 |
| 心跳票据 | 1Hz HMAC 链 + seq | 0.5 天 |
| **蜜罐分支** | 检测调试不崩溃，改签诱饵票据 | 1 天 |

### 关键设计

```
K = KDF( hash(anticheatd .text) ‖ hash(fgfs) ‖ hash(aircraft data) ‖ userid ‖ nonce )
```

- K 只存在于内存，用完即擦
- **flag 生成用 `K_server`，不用 K** —— 否则挖出反作弊 key 就能算出 flag1/flag2，造成连带崩塌
- 心跳中断即整场作废，使"绕过" = "逆向 + 内存攻防"，而非"删文件"

### 风险（最高优先级阶段）

| 风险 | 缓解 |
|---|---|
| **anti-VM 误杀**（Hyper-V / WSL2 / 核心隔离 / 第三方反作弊） | 必须发布操作指引 + 提供自检工具，开赛前一周开放自检 |
| 反作弊稳定性问题导致选手正常游戏崩溃 | 先内测 5 台不同硬件；检测失败默认"告警"而非"退出"，只有 L0/L1 直接拒绝启动 |
| 蜜罐分支自己写错，导致真分支永远走不到 | 单独写单元测试：模拟调试态，断言签出的是诱饵 key |
| 反反调试被 Frida 一把梭 | 不必追求不可破；目标是让选手必须做真实逆向工作 |

## P4 · flag3 判定与联调（3 天）

### 任务

- [ ] 三检查点判定：飞天（>100,000ft ≥10s）/ 遁地（AGL < -300ft ≥10s）/ 超速（>3×VNE ≥15s）
- [ ] 平滑性与持续性校验（防瞬移刷分）
- [ ] 服务端差分地速 vs 客户端上报马赫数交叉验证
- [ ] 端到端联调：出题意外路径验证（自己实现一次完整攻击，确认能拿 flag）
- [ ] 反向验证：确认 L0–L3 各条低成本路径确实被封

### 关键决策点

- flag3 走**独立实例 / 独立频道**：有人在主服务器 Mach 5 穿地会撞穿别人的飞机，还会当场剧透给全场
- 判定通过后才在排行榜显示

### 风险

| 风险 | 缓解 |
|---|---|
| 出题组自己也没把握能做出 flag3 | P4 必须自己完整走一遍攻击链，做不出来就砍蜜罐分支降一档难度 |
| 判定过严无人通过 | 分档：达成任意 2 个检查点给部分分 |

### 任务

- [ ] 参赛者镜像 / 容器 + 一键 `launcher.sh`
- [ ] `anticheat-selfcheck` 自检工具
- [ ] **《关闭虚拟化操作指引》**（Windows：`bcdedit /set hypervisorlaunchtype off`、关闭核心隔离、关闭 WSL2；Linux：卸载 kvm / BIOS 关 VT-x）
- [ ] 题目面（三道题的题面文本、hint 分级）
- [ ] 评分与 Writeup 加分规则

### 关键决策点

- hint 分级是难度旋钮：是否给"信号/状态源不可信"的提示，直接决定 flag3 的通过率

## 验收测试清单

上线前必须全部打勾：

**环境**
- [ ] 干净物理机从零按文档部署成功
- [ ] 自检工具能正确识别已/未关闭虚拟化

**flag1**
- [ ] stock AP 直飞能通过并拿到基础分（但拿不满）
- [ ] 手飞好进近能拿满分
- [ ] 故意摔地/偏离航道不给分

**flag2**
- [ ] 正确解算并飞抵触发
- [ ] 瞬移擦边不触发

**flag3**
- [ ] **出题组自己完整实现一次攻击并成功拿到 flag**
- [ ] `--fdm=ufo/magic/null` 被 L0 拒绝
- [ ] `--fdm=external` 被 L0 拒绝（正式模式）
- [ ] 改机型 XML 被 L1 拒绝
- [ ] telnet 写 `/position/*` 被 L2 拦截
- [ ] `kill` 反作弊 → 心跳中断 → 会话作废
- [ ] 挂调试器 → 拿到的是诱饵票据而非真 flag
- [ ] 在虚拟机内运行 → anti-VM 拦截

**平台**
- [ ] 多人同时在线，判决互不干扰
- [ ] 重放旧轨迹被 nonce/时间戳拒绝
- [ ] challenge 注入后响应时延校验生效
